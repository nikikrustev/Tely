# 21 — Keeping the demo live, cheap and judge-proof through judging (ops, cost, security)

_Accessed/compiled: 20 Oct 2026 · Priority area: operations for the submitted demo (Render + Personalise front end, Explain backend), cost control, security, CI/CD_

## TL;DR

- **Build a "replay mode" first, and make it the default the judges land on.** It is a recorded, seeded match whose cue JSON (every audience and language), events and video were all produced earlier by our real pipeline. It ships as static files on Static Web Apps (SWA). It needs no backend, no LLM and no quota, so it costs about $0 and can't go down because of us. The live backend becomes an optional "Run live" button that falls back to replay on any error.
- **Our minimal judge stack costs about $25-35 for 3 weeks at East US 2 list prices.** Container Apps (ACA) with `minReplicas: 1` at 0.25 vCPU / 0.5 GiB costs about $2.46 if mostly idle, or about $8.21 if always active. The standard availability test is the surprise line item: $0.0005 per run, so 5 locations every 5 minutes cost $15.12. Web PubSub Standard ($1.61/day) and Event Hubs Standard ($0.03/h) would add about $49, so leave them out of judge mode. All arithmetic is below.
- **Uptime:** one Application Insights **standard** availability test (5-minute frequency, 3 locations, content match on the replay page), alerting to email and Azure-app push. Azure Monitor **does not support SMS to Bulgaria (+359)**, but it does support the UK (+44). Add a free GitHub Actions cron smoke test, and use its badge as the README status badge.
- **Abuse:** no free-text prompts on the public path (preset questions only), a per-IP limit and a global daily LLM budget enforced in FastAPI, every LLM output cached, a `DEMO_MODE` kill switch, and a low TPM capacity on the deployment as a hard ceiling. Cost Management budgets **don't stop spending** and are only evaluated every 24 hours, so they are a backstop, not a brake.
- **Secrets and CI/CD:** no keys anywhere. GitHub Actions authenticates with OIDC through `azure/login@v2`, then `azd deploy`. The app uses managed identity for Foundry and Key Vault. There are two azd environments (`dev` and `judge`) in separate resource groups, both tagged. The rules allow post-deadline edits only to remove infringing or PII material (see research 12), so **freeze `judge` at the deadline** and change only ops toggles.

## Findings

### 1. Replay mode: near-zero-cost architecture

**Why:** SWA serves static files from a globally distributed host. A static replay therefore keeps working even when our ACA app is scaled to zero, the Foundry quota returns 429s, or a deploy breaks the backend.

```
build time (CI or laptop)                        judge time
seeded simulator -> real pipeline -> cues   ┌─> SWA (static, Free or Standard)
  (same code as live, LLM called once)       │     /replay/<match>/manifest.json
  -> /replay/<match>/{events.ndjson,         │     /replay/<match>/cues.json (+ .vtt, see research 04)
      cues.json, cues.vtt, video.mp4}  ──────┘     video.mp4 (or Blob Hot LRS if > SWA size limit)
front end: try /api/health (2 s timeout) -> live mode, else replay mode; ?mode=replay forces it
```

- **Same renderer for both modes.** The replay loader only swaps the cue *source* (a file instead of a WebSocket). Judges see the real overlay code, and the "truth_check" and evidence IDs are real because they were computed by the pipeline. Label it honestly with a banner such as "Replay of synthetic match #seed 4211, generated by the live pipeline on 26 Oct".
- **Size limits on SWA:** 250 MB per environment and 500 MB in total on Free (500 MB / 2 GB on Standard), at most 15,000 files, and 100 GB of included bandwidth per month. **Free has no bandwidth overage: it is "unavailable".** Put a large video in Blob Storage (Hot LRS stores data at $0.0184/GB-month in East US 2) and keep the JSON in SWA.
- **Caching:** set `Cache-Control` per route in `staticwebapp.config.json`, for example `public, max-age=604800, immutable` on `/replay/*.json`. Version the folder name (`/replay/v3/...`) instead of busting caches.
- **Free vs Standard SWA.** Free has **no SLA**. Standard costs $9/month, has an SLA, and allows **linking ACA as the `/api` backend**. When linked, "the container app only accepts requests that are proxied through the linked static web app", which gives us same-origin calls and a free shield against direct abuse of the ACA URL. This is the main reason to pay the $9.

### 3. Uptime monitoring and alerting

- **Standard test** is the current kind. URL ping tests are deprecated and retire on 30 Sep 2028. A standard test checks the status code, a case-sensitive **content match**, TLS validity with a proactive lifetime check, custom headers and the HTTP verb. The minimum frequency is 300 s, and each Application Insights resource can hold up to 100 tests. Enable retries: a failure is then reported only after 3 consecutive failed attempts, and "about 80% of failures disappear on retry".
- **Locations:** the docs recommend at least 5, with an alert threshold of locations − 2. Three locations with `failedLocationCount: 2` is the cost-saving compromise. Config changes can take up to 20 minutes to reach all test agents.
- **What to test:** (a) the SWA replay page with content match on a string the app renders only when healthy, for example `data-health="ok"`. (b) Optionally `/api/health` through SWA. A linked ACA rejects direct traffic, so always test through SWA.
- **Alerts are state-based:** one notification when the site goes down and one when it recovers. Without an action group you only get in-portal notifications.
- **Action group limits:** at most 1 SMS and 1 voice call every 5 minutes per number, and at most 100 emails per hour per address. **SMS and voice country lists don't include Bulgaria (+359)**, so use email plus **Azure mobile app push** (up to 10 per group), or a UK number. A new email receiver must confirm a one-time passcode within 30 minutes.
- **README badge:** we found no built-in public badge for availability tests. Instead, add a GitHub Actions `schedule` workflow that curls the demo and fails if the health string is missing, and show its badge: `https://github.com/OWNER/REPO/actions/workflows/uptime.yml/badge.svg`. Caveats: the minimum interval is 5 minutes, runs "can be delayed during periods of high loads", scheduled runs happen on the default branch only, and they are auto-disabled after 60 days without repository activity. GitHub-hosted minutes are free for public repos (unverified).

### 4. Abuse protection for a public LLM demo

| Risk | Control |
|---|---|
| Prompt injection, offensive output | **No free-text box on the public path.** Use preset question chips (e.g. "Why did pressure flip at 61'?"), which become cache keys. If D Chalk Talk / 22 Half-Time Talk needs typed questions, cap them at 200 characters and 3 per IP per 10 minutes, and enable **Prompt Shields**. Default filters return **HTTP 400 `content_filter`** for a filtered prompt and `finish_reason: "content_filter"` for a filtered completion, so show a canned cue in either case. If the filter service is down, the call **completes unfiltered**, with an error in `content_filter_results`. Check for that and drop the output. |
| Cost runaway | (1) Set the deployment's TPM capacity low. The Tier 1 quota for `gpt-5.4-mini` Global Standard is **1,000 RPM / 1,000,000 TPM**. Our arithmetic: 1M TPM × 60 min = 60M tokens/h, which at $4.50/1M output is up to **$270/hour**. At 10K TPM the worst case is 14.4M tokens/day, or $64.80/day if all of it is output. (2) Enforce an in-app global daily token budget. (3) Set `maxReplicas: 2`. (4) Add a budget with an action group as a last-resort email. It is evaluated every 24 h on data that is 8-24 h old, and "consumption isn't stopped". |
| Request floods | Per-IP sliding window in FastAPI (snippet below). With one replica, in-memory counters are exact. SWA and ACA have no built-in per-IP rate limiting that we found. **APIM `rate-limit-by-key` isn't available on the Consumption tier**: it applies to Developer, Basic, Basic v2, Standard, Standard v2, Premium and Premium v2. Even where it is available, "rate limiting is never completely accurate". |
| Repeat cost | Cache LLM outputs by `sha256(seed, moment_id, audience, lang, prompt_version)` in Blob or Cosmos. A replay file is a pre-baked cache. |
| Bad day | **Kill switch** `DEMO_MODE=live|cached|replay`, read on every request: `az containerapp update -n api -g rg-judge --set-env-vars DEMO_MODE=replay`. An env-var change creates a new revision, which takes a minute or so (unverified). The front end treats any non-200 from `/api/config` as replay. |
| Keys in the browser | None. ACA uses managed identity with the **Cognitive Services OpenAI User** role (research 03). Other secrets go in Key Vault as **Key Vault references** (`keyvaultref:...,identityref:...`), with the **Key Vault Secrets User** role. Unversioned references pick up new versions within 30 minutes, and revisions are restarted automatically. |

### 5. Secrets and CI/CD

- **OIDC:** create a user-assigned managed identity, or an Entra app, with a **federated credential** per GitHub environment (`az identity federated-credential create ... --issuer https://token.actions.githubusercontent.com --subject repo:OWNER/REPO:environment:judge --audiences api://AzureADTokenExchange`). The subject string format comes from GitHub's OIDC docs (not fetched, unverified). A typo in the subject fails silently at token exchange. There is a maximum of 20 federated credentials per identity, and wildcards aren't supported. The workflow needs `permissions: id-token: write`.
- **azd:** `azd pipeline config --provider github --auth-type federated -e judge` creates the principal and the federated credential, and sets the `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `AZURE_ENV_NAME` and `AZURE_LOCATION` variables. Use `azd env new dev` / `azd env new judge` with separate subscriptions or resource groups. azd can reuse an `azure/login` session via `azd config set auth.useAzCliAuth "true"`.
- **Environments:** use GitHub Environments `dev` (auto-deploy on push to main) and `judge` (manual `workflow_dispatch` with required reviewers). Microsoft recommends environment secrets for public repos, because a job can't read them until a reviewer approves.
- **Tags:** tag everything `azd-env-name=<env>`. This is the azd sample-template convention, not a formal spec. Also add `project=berbata`, `purpose=hackathon-judging` and `delete-after=2026-11-21`. Filter the budget by resource group.

**FastAPI: per-IP rate limit, daily LLM budget and kill switch** (single replica, in-memory)
```python
import os, time, collections
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()
WINDOWS = {"/api/explain": (5, 600), "default": (60, 60)}   # (max calls, seconds)
hits: dict[tuple[str, str], collections.deque] = collections.defaultdict(collections.deque)
DAILY_LLM_CAP = int(os.getenv("DAILY_LLM_CALLS", "500")); llm_calls = {"day": "", "n": 0}

def client_ip(req: Request) -> str:
    xff = req.headers.get("x-forwarded-for", "")   # set by SWA/ACA ingress (unverified)
    return xff.split(",")[0].strip() or (req.client.host if req.client else "?")

@app.middleware("http")
async def guard(req: Request, call_next):
    path = req.url.path
    if path == "/api/health":
        return await call_next(req)
    mode = os.getenv("DEMO_MODE", "live")                  # live | cached | replay
    if mode == "replay" and path.startswith("/api/"):
        return JSONResponse({"mode": "replay"}, status_code=503)
    limit, win = WINDOWS.get(path, WINDOWS["default"])
    key, now = (client_ip(req), path if path in WINDOWS else "default"), time.time()
    q = hits[key]
    while q and q[0] <= now - win: q.popleft()
    if len(q) >= limit:
        return JSONResponse({"error": "slow down", "fallback": "replay"}, status_code=429,
                            headers={"Retry-After": str(int(win - (now - q[0])) + 1)})
    q.append(now)
    if path == "/api/explain":
        today = time.strftime("%Y-%m-%d")
        if llm_calls["day"] != today: llm_calls.update(day=today, n=0)
        if mode == "cached" or llm_calls["n"] >= DAILY_LLM_CAP:
            req.state.cache_only = True                     # handler serves cache or canned cue
        else:
            llm_calls["n"] += 1
    return await call_next(req)
```

**TypeScript: replay-mode loader and scheduler** (same `render(cue)` as live)
```ts
type Cue = { cue_id: string; tc_in_ms: number; ttl_ms: number; layout: string;
             text: Record<string, string>; evidence: string[]; truth_check: string };

export async function pickMode(): Promise<"live" | "replay"> {
  if (new URLSearchParams(location.search).get("mode") === "replay") return "replay";
  try {
    const r = await fetch("/api/config", { signal: AbortSignal.timeout(2000) });
    return r.ok && (await r.json()).mode === "live" ? "live" : "replay";
  } catch { return "replay"; }
}

export async function startReplay(base: string, video: HTMLVideoElement,
                                  render: (c: Cue) => void, clear: (id: string) => void) {
  const manifest = await (await fetch(`${base}/manifest.json`)).json(); // {cues:"cues.json", video:"..."}
  const cues: Cue[] = (await (await fetch(`${base}/${manifest.cues}`)).json())
    .sort((a: Cue, b: Cue) => a.tc_in_ms - b.tc_in_ms);
  video.src = manifest.video;
  const shown = new Map<string, number>();            // cue_id -> expiry (ms)
  let next = 0;
  const tick = () => {
    const t = video.currentTime * 1000;
    if (next > 0 && t < cues[next - 1].tc_in_ms) {    // user seeked backwards
      next = cues.findIndex(c => c.tc_in_ms >= t); if (next < 0) next = cues.length;
      shown.forEach((_, id) => clear(id)); shown.clear();
    }
    while (next < cues.length && cues[next].tc_in_ms <= t) {
      const c = cues[next++]; render(c); shown.set(c.cue_id, c.tc_in_ms + c.ttl_ms);
    }
    shown.forEach((exp, id) => { if (t >= exp) { clear(id); shown.delete(id); } });
    requestAnimationFrame(tick);
  };
  requestAnimationFrame(tick);
}
```
